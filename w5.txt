互動式網頁設計｜第 5 週作業
專題：黑貓街機廳（Unity 遊戲 → 專題介紹網站）
本檔用途：需求拆解、Prompt 對話紀錄、架構規劃（本週不產完整程式碼）

================================================================================
需求拆解表
================================================================================

【一、目標】

1. 把已完成的 Unity 專題「黑貓街機廳」轉成「給外人快速看懂」的介紹網站，不是再做新遊戲、也不是重做 Unity 功能。

2. 主要情境：掃專題海報 QR Code，用手機或筆電打開，在短時間內知道這是什麼遊戲、怎麼玩、專題做了什麼。

3. 主要頁面固定三頁（index.html / game.html / project.html），不再增加其他主要頁面。

4. 首頁：快速看懂遊戲，不放大量技術內容。

5. game.html：玩法、操作、專題內小遊戲／街機內容、畫面或展示影片、遊戲入口；其中尚無定稿的項目在規劃階段標「待確認／待補」，不先寫假內容。

6. project.html：製作目的、開發流程、團隊分工、使用技術；分工與技術清單待從專題簡報／報告確認後填入，只列確定用過的項目。

7. 桌機與手機共用同一組三個 HTML，之後以 CSS Media Query 做 RWD。

8. 檔案結構簡單，方便之後 push 到 GitHub Repository（例如 GitHub Pages 托管靜態站）。


【二、畫面功能】

■ 全站共通
- 導覽：首頁、遊戲介紹、專題介紹（index.html、game.html、project.html）。
- 桌機／手機同一套頁面，RWD 用 css/style.css 的 Media Query，不另建 mobile.html。

■ 首頁（index.html）
- 遊戲名稱與主視覺
- 簡短介紹（文案：待從海報／簡報確認）
- 3 個主要特色（內容：待從專題資料確認）
- 3～5 張遊戲截圖（素材：待從專題確認）
- 前往「遊戲介紹」「專題介紹」的按鈕
- 不放：開發流程、團隊分工、使用技術等（集中在 project.html）

■ 遊戲介紹頁（game.html）
- 實際玩法（待從 Unity 專題／簡報確認）
- 操作方式（待確認）
- 小遊戲／街機內容（名稱與說明：待從專題核對，不先列假項目）
- 遊戲畫面或展示影片（待補；沒有素材就不假裝有）
- 遊戲入口／下載連結：待確認（確認後再放；沒有則頁面標註即可）

■ 專題介紹頁（project.html）
- 製作目的（待從簡報／報告確認）
- 開發流程（待從專題資料確認）
- 團隊分工（待確認；若專題無分工資料則不寫）
- 使用技術（待確認；只列專題確定用過的項目，不自行補名詞）


【三、資料來源】

皆以「黑貓街機廳」Unity 專題與既有交付物為準；w5 階段尚未對照的欄位一律標待確認／待補。

| 類型 | 用途 | 備註 |
|------|------|------|
| 專題海報 | 首頁主視覺 | 文案、視覺與海報一致 |
| 專題簡報／報告 | 首頁短介、特色；project 目的、流程、分工、技術 | 改寫成網頁用語，事實不變 |
| Unity 專案／Build 文案 | game 頁玩法、操作、小遊戲說明 | 待對照專案核對 |
| 遊戲截圖 | 首頁 3～5 張；game 頁必要時再用 | 專題產出，待整理 |
| 展示影片 | game 頁 | 待補 |
| 遊戲入口／下載連結 | game 頁 | 待確認 |
| 小遊戲／街機項目名稱 | game 頁 | 待從專題核對 |
| 操作方式 | game 頁 | 待確認 |
| 團隊分工 | project 頁 | 待確認 |
| 使用技術清單 | project 頁 | 待確認 |
| w5.txt | 需求、Prompt、架構 | 本週作業；內含規劃，非程式成品 |


【四、限制條件】

1. 專題名稱「黑貓街機廳」，資料來源為已完成的 Unity 專題，不改成其他虛構專題或世界觀。

2. 主要頁面僅 index.html、game.html、project.html，不再增加其他主要頁面。

3. 本週僅 w5.txt 規劃文件；不產出完整 HTML、CSS、JavaScript 成品（本檔不出現可執行的網頁程式碼）。

4. 不編造玩法、小遊戲名稱、操作、下載網址、影片、技術、分工；無真實資料處標「待確認／待補」。

5. 不做登入、商城、付款、會員等目前沒有的功能。

6. 不另建 mobile.html；RWD 僅用 CSS Media Query。

7. 遊戲入口／下載連結不預設存在、不寫死特定平台名稱；確認前統一「待確認」。

8. 檔案結構保持簡單、適合 GitHub；不把 Unity 整包專案塞進同一 repo。
